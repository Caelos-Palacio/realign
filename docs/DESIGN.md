# Realign design and guarantees

Realign separates three responsibilities: rules declare which relations to check; the interpreter evaluates data within a closed grammar; the agent investigates intent and proposes changes. A clean result shows agreement with the available rules, not general semantic truth.

## Independent contract

A behavior contract fixes input scenarios and expected outputs, including decision, sequence and simulated effects. Expectations are not generated by running the policy under evaluation. In a repair, these criteria are preserved. Changing a contract is a change of intent that needs separate justification and review, even if the change makes tests pass.

A baseline binds bytes to a revision; it does not prove that the revision is correct, independent, or earlier than every run. It must not be regenerated automatically to resolve a disagreement. Version-control history and human review still matter.

## Bounded semantic preservation

The explicit grammar can test negation, conjunction/disjunction, comparisons and rule priority. Comparisons on a missing path return false, including `ne`; `exists` is true for a present `null`. `not` is boolean negation, not an unknown state: it can turn a missing comparison into true. When absence must not be allowed, also declare existence or an explicit positive equality. The interpreter does not freely interpret a README nor prove that a policy represents the user's intent. `trace` and `effects` are JSON values: they run no tools and prove no real effects.

Scenarios should include boundaries, missing inputs, revocations, exceptions and valid examples. A verifier that rejects everything must fail for lack of allowed outcomes. A detected mutation means the corpus distinguishes that specific alteration; by itself it does not measure full coverage, general quality or the absence of equivalent mutants. Results must keep denominators and surviving mutants.

## Cost and incrementality

Do not add a generic graph or a cache before defining all dependencies of each check, including interpreter version, configuration, contract and authority. An incomplete cache can turn a regression into a stale clean result. Measure checking, evaluation, repair and verification separately, including retries. Free-form agent inference has a different cost and different guarantees from deterministic evaluation.

## Operational limits

Automatic repairs remain limited to declared derived blocks. Contracts, authorities and data are verified, never modified to get a green result. The lock is cooperative; there is no durable multi-file transaction and no isolation from an adversarial writer. The hook inspects a snapshot of the index, but does not prevent later changes or its being skipped.

## Local grounding

This design applies bounded conclusions from local research: E6 showed tests agreeing with a semantically wrong oracle; E3 showed that different sequences can share a final state; E4 did not show general savings from summarizing; the flow model makes invalidation conditional on complete dependencies. The experimental E6 interpreter is not reused as a validated verifier.
